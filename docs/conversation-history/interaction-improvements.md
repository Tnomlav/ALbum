## 5. Codex (final_answer)

从现有代码和页面结构看，App 的功能已经比较完整，但交互上存在“功能多、入口分散、反馈偏弱”的问题。建议优先关注这些：

### 高优先级

1. **删除操作缺少明显的撤销入口**

目前删除后主要通过 Toast 提示，用户无法快速撤销。尤其是批量删除、清空回收站、彻底删除，风险较高。

建议：

- 删除完成后显示 Snackbar：`已删除 12 项` + `撤销`
- 对批量操作显示具体数量和失败数量
- “彻底删除”使用更强的二次确认，例如输入确认文字或明确说明不可恢复

相关代码：[AlbumApp.kt](<LOCAL_PATH>/AndroidStudioProjects/Album/app/src/main/java/com/example/album/ui/AlbumApp.kt)

2. **多选模式的发现性不足**

目前主要依赖长按进入多选：

```kotlin
onLongPressMedia = { ... selectionMode = true ... }
```

新用户可能不知道可以长按。建议增加：

- 顶部或更多菜单中的“选择”
- 首次使用时提示一次“长按进入多选”
- 进入多选后，在媒体项上显示明确的勾选状态
- 支持拖动连续选择，提升批量操作效率

3. **顶部操作栏承载过多功能**

普通页面和多选页面都有较多操作，部分功能被放进“三点菜单”中，例如编辑、信息、标签、壁纸、排除等。用户很难判断哪些操作在哪里。

建议按优先级分组：

- 高频：收藏、分享、删除、移动
- 中频：编辑、信息、重命名
- 低频：排除、设置壁纸、打开方式

同时可以在首次进入相关页面时提供简短的引导，而不是让用户逐项试错。

4. **页面层级较多，返回逻辑需要更明确**

当前存在：

- 普通浏览
- 文件夹浏览
- 多选
- 媒体查看器
- 编辑器
- 清理页面
- 回收站
- Pixiv 归档页面

代码中已经有较复杂的 `BackHandler` 状态判断。功能上可能可用，但用户需要明确知道当前处于哪一层。

建议：

- 子页面顶部统一显示返回按钮和标题
- 查看器返回编辑器时，标题或按钮应明确显示“返回编辑”
- 多选模式退出时，如果已有选择，应提示“退出后将清除选择”
- 清理、回收站、Pixiv 归档最好使用明确的页面标题，而不是仅靠状态变化

### 中优先级

5. **图片、视频切换入口不够直观**

目前标题旁通过 `SwapHoriz` 图标切换图片和视频：

```kotlin
onTitleClick = ...
```

这属于隐藏功能，用户可能不知道标题可以点击。建议改为：

- 使用“图片 / 视频”分段控件
- 或者在标题下方放 Tab
- 图标保留，但不要单独依赖图标表达切换关系

6. **搜索模式切换不够符合常见习惯**

搜索栏旁通过点击文字和交换图标切换搜索方式。对于 Pixiv 的作者 / 标签搜索，这种方式不如显式的 SegmentedButton 或下拉菜单直观。

建议显示：

- 作者
- 标签

并明确标注当前模式，而不是只依赖 `SwapHoriz` 图标。

7. **空状态反馈不够有行动指引**

目前空页面主要显示：

- “这里还没有图片”
- “没有找到相关内容”

建议区分不同状态：

- 没有访问权限：显示“去授权”
- 没有媒体：显示“重新扫描”
- 搜索无结果：显示“清除搜索”
- 文件夹为空：显示“返回上级”或“打开其他文件夹”

空状态应该直接给出下一步操作。

8. **扫描、复制、移动等异步操作的进度反馈不足**

代码中较多操作通过 Toast 告知结果，但用户在等待过程中可能不知道任务是否仍在执行。

建议：

- 显示顶部或底部进度条
- 显示“正在扫描 132/846”
- 支持取消长时间任务
- 任务失败时提供“重试”
- 对部分成功的批量任务说明成功和失败数量

9. **设置页信息密度偏高**

设置页包含主题、权限、回收站、视频、显示、滚动条、幻灯片、缓存、更新等大量选项。虽然已经分组，但页面很长，查找成本较高。

建议：

- 增加设置页顶部搜索
- 对低频配置折叠分组
- 将“权限”和“文件操作”放到更靠前的位置
- 给关键设置增加当前状态摘要
- 对“默认界面”“默认排序”等常用项放入单独的“常用设置”

10. **部分开关和自定义控件可能存在可访问性问题**

项目中有很多自定义 Canvas 控件、滑杆和点击区域，例如：

```kotlin
Canvas(Modifier.size(48.dp).clickable(...))
```

这类控件可能缺少：

- TalkBack 可读描述
- 明确的 checked 状态
- 键盘 / 无障碍操作支持
- 足够清晰的点击反馈

建议尽量使用 Material 现成的 `Switch`、`Slider`、`Checkbox`，或者为自定义控件补充 semantics。

### 体验细节

11. **中英文文案风格不完全统一**

例如：

- `Tags`
- `View/Edit Tags`
- `Pixiv`
- `Update`
- 部分设置使用中文值，部分使用英文值

建议建立统一的文案表，避免中英文混用，也避免同一功能出现多个叫法。

12. **Toast 使用较多，重要反馈容易消失**

Toast 适合短提示，但不适合：

- 删除结果
- 批量任务结果
- 更新失败
- 权限状态变化
- 文件复制失败

这些更适合使用 Snackbar、对话框或持久化的结果面板。

13. **底部导航支持拖动重排，但学习成本较高**

目前需要在设置中开启“长按移动底栏图标”，然后再长按拖动。这个功能比较隐蔽，也可能让普通点击和长按产生冲突。

建议：

- 在设置中提供明确的“编辑导航栏”页面
- 进入编辑后显示拖动把手
- 提供“恢复默认顺序”
- 显示当前导航顺序预览

14. **文件夹和媒体操作的对象边界需要更清楚**

多选时既可以选择文件夹，也可以选择媒体，部分操作对文件夹有效、部分只对媒体有效。建议在顶部显示当前模式，例如：

- `已选择 3 个文件`
- `已选择 2 个文件夹`
- `文件夹模式`

并对不可用操作给出原因，而不是仅显示禁用图标。

### 建议优先级

我建议按这个顺序改进：

1. 删除后的撤销和批量结果反馈  
2. 多选入口和多选状态  
3. 返回层级与页面标题  
4. 空状态和扫描进度  
5. 图片 / 视频切换和搜索模式  
6. 设置页整理  
7. 无障碍与自定义控件  
8. 文案统一和底栏重排体验  

总体来看，App 目前的主要问题不是缺少功能，而是功能的可发现性、操作后的反馈，以及高风险操作的可恢复性还不够强。
