> 测量时间：2026-09-22
> 方法：直接读取 APK 内每个条目的原始大小与压缩后大小（`zipfile`），不依赖构建日志

## 结论

**体积由两块决定：LibVLC 的原生库（约 23 MB 压缩后）与编辑器中文字体（约 31.5 MB 压缩后）。**
两者相加占了安装包的约九成，`dalvik` 代码、其余资源与 assets 合计不到 6 MB。

已经做到位的部分（不需要再动）：

- R8 混淆 + 资源压缩与资源名重命名已开启（所以体积里没有未引用资源）。
- `androidResources.localeFilters = ["en", "zh"]`，AndroidX/Media3 的其它语言资源没有进包。
- release 按 ABI 分包（`arm64-v8a` / `armeabi-v7a` / `x86_64`），随包分发的只有对应架构的原生库。
- 依赖体积较大的 `libvlc-all` 只用于 Media3 解不动的 AVI/MPEG-PS 兼容回退。

## 可选优化路径（按风险从低到高）

1. **确认 LibVLC 只随需要的渠道分发**（低风险，需要产品决策）。示例视频、AVI 回退之外，普通用户的绝大部分视频走 Media3；若发行渠道允许，可发布"精简版"（无 LibVLC）与"完整版"，安装包直接少约 23 MB。
2. **字体按需下载**（中风险，需要托管与首次使用引导）。十款字体只在编辑器的"文字"工具里用；改成首次使用某款字体时下载，可省下接近一半安装包。代价是离线首次使用需要联网。
3. **字体子集化 + 系统字体回退**（高风险）。把每款字库裁到常用汉字集，理论上能再省一半以上；但用户输入的生僻字必须回退到系统字体，而 `Typeface.CustomFallbackBuilder` 只在 Android 10+ 可用，minSdk 24 需要另一条路径，属于必须真机逐款验证的独立工作。

在 1.2.x 阶段不动这三项，保持"装上即用、离线可用"的取舍；需要减包时按 1 → 2 → 3 的顺序推进。
